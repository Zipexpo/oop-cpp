Tính đa hình ​

Chương này ăn điểm ở đâu trong đề thi

  • Dùng đúng hàm ảo và override2 điểm, có ở 12/12 đề
  • Đa hình hoạt động đúng với con trỏ1 điểm

5.1 Một từ khoá sửa vấn đề của chương 4 ​

Cuối chương 4, p->display() gọi nhầm hàm của lớp cha. Lý do: mặc định, C++ chọn hàm dựa vào kiểu của con trỏ (Document*), quyết định ngay lúc biên dịch. Nó không nhìn xem con trỏ đang thật sự trỏ tới cái gì.

Hai chữ của bài giảng tuần 7

Liên kết tĩnh (static binding). Trình biên dịch quyết định gọi hàm nào ngay lúc dịch, dựa vào kiểu khai báo của biến. Đây là mặc định, và là thứ đã làm hỏng bài 4.6.

Liên kết động (dynamic binding). Việc chọn hàm bị hoãn tới lúc chạy, dựa vào đối tượng thật. Từ khoá virtual chính là công tắc bật chế độ này.

Bài giảng tuần 7 dùng đúng hai thuật ngữ này; sách dùng lại để bạn khỏi phải học hai bộ từ vựng.

Thêm virtual là bảo trình biên dịch: “hàm này đừng quyết vội, tới lúc chạy hãy nhìn đối tượng thật rồi mới chọn”.

cpp
class Document {
    // ...
public:
    virtual void display() const;       // them virtual
    virtual int  loanDays() const;      // so ngay duoc muon
    virtual ~Document();                // BAT BUOC - xem muc 5.5
};

class Book : public Document {
    // ...
public:
    void display() const override;      // them override
    int  loanDays() const override;
};

Chạy lại đúng đoạn code cũ, không sửa một chữ nào trong main:

text
[SACH] S001 | Lap trinh huong doi tuong | Bjarne Stroustrup | 2019 | 350 trang | Con 2 ban
[SACH] S001 | Lap trinh huong doi tuong | Bjarne Stroustrup | 2019 | 350 trang | Con 2 ban

Đó là toàn bộ tính đa hình: cùng một lời gọi, đối tượng nào thì chạy phần của đối tượng đó.

5.2 virtual đặt ở đâu, override đặt ở đâu ​

Từ khoáĐặt ởBắt buộc?Tác dụng
virtualLớp chaCóBật cơ chế chọn hàm lúc chạy
overrideLớp conKhông, nhưng luôn nênBáo lỗi nếu bạn ghi đè hụt

Vì sao override quan trọng dù không bắt buộc

Giả sử lớp cha có void display() const còn bạn gõ ở lớp con là void display() — thiếu const. Không có override, trình biên dịch coi đó là một hàm mới, khác, im lặng chấp nhận, và đa hình không hoạt động. Bạn sẽ ngồi dò cả buổi.

Có override, nó báo ngay: error: 'void Book::display()' marked 'override', but does not override.

Chữ ký phải khớp tuyệt đối: tên hàm, danh sách tham số, và cả const ở cuối.

5.3 Đa hình chỉ chạy qua con trỏ hoặc tham chiếu ​

cpp
Book b("S001", "Lap trinh HDT", 2019, 2, "Stroustrup", 350);

Document* p = &b;     p->display();      // [SACH] ... dung
Document& r = b;      r.display();       // [SACH] ... dung
Document  d = b;      d.display();       // [TL]   ... SAI!

Object slicing — cái bẫy im lặng

Dòng cuối sao chép phần Document của b vào một đối tượng Document mới. Phần author và pages bị cắt mất — nên gọi là “thái lát”. Không có lỗi, không có cảnh báo, chỉ có kết quả sai.

Quy tắc: muốn giữ đa hình thì giữ con trỏ (Document*) hoặc tham chiếu (const Document&), không bao giờ chép vào biến kiểu lớp cha.

Đây cũng là lý do mọi đề thi đều yêu cầu vector<Vehicle*> chứ không phải vector<Vehicle>.

5.4 Dạng bài luôn xuất hiện trong đề thi ​

Gần như đề nào cũng có đúng khuôn này. Học thuộc nó:

cpp
Document* ds[3];
ds[0] = new Book("S001", "Lap trinh HDT", 2019, 2, "Stroustrup", 350);
ds[1] = new Magazine("TC001", "Vat ly Ngay nay", 2024, 4, 57, 9);
ds[2] = new Disc("D001", "Thi nghiem quang hoc", 2022, 1, 45);

for (int i = 0; i < 3; i++)
    ds[i]->display();        // moi dong mot dinh dang khac nhau

for (int i = 0; i < 3; i++)
    delete ds[i];            // nho tra lai bo nho

std::vector — thứ đề thi đòi mà bài giảng không dạy ​

Phần này bài giảng chưa phủ

Chữ vector xuất hiện 0 lần trong tám tuần slide lý thuyết. Nhưng đề thi ghi thẳng: “Tạo vector chứa Vehicle*”. Nên phải học ở đây. Tin tốt: bạn chỉ cần đúng bốn dòng dưới đây, không cần gì hơn cho cả môn.

vector là một mảng tự nới rộng — không phải khai báo trước sức chứa, không phải new[], không phải delete[]. Bốn việc cần biết:

ViệcViếtGhi chú
Khai báovector<Document*> ds;Cần #include <vector>
Thêm vào cuốids.push_back(con_tro);Tự nới rộng, không giới hạn
Số phần tửds.size()Trả về số nguyên không dấu
Duyệtfor (Document* d : ds)Hoặc for (size_t i = 0; i < ds.size(); i++)
cpp
#include <vector>

std::vector<Document*> ds;
ds.push_back(new Book("S001", "Lap trinh HDT", 2019, 2, "Stroustrup", 350));
ds.push_back(new Magazine("TC001", "Vat ly Ngay nay", 2024, 4, 57, 9));

for (Document* d : ds)  d->display();
for (Document* d : ds)  delete d;      // van phai tu delete!

Hai điều rất hay nhầm về vector

1. vector tự dọn chỗ chứa con trỏ, nhưng không dọn các đối tượng mà con trỏ trỏ tới. Bạn vẫn phải tự delete từng phần tử, đúng như mục 3.5 đã nói.

2. Phải là vector<Document*>, không phải vector<Document>. Loại thứ hai cắt mất phần lớp con (object slicing, mục 5.3) và đa hình sẽ không chạy. Đây là lý do mọi đề thi đều viết dấu sao.

So với mảng con trỏ ở chương 3: vector gọn hơn và không cần đếm sức chứa. Đề thi chấp nhận cả hai, nhưng khi đề đã ghi vector thì hãy viết vector.

Hành vi khác nhau, không chỉ là in khác nhau ​

Đa hình mạnh nhất khi nó trả về dữ liệu khác nhau, không chỉ in khác nhau. Hạn mượn phụ thuộc loại tài liệu:

text
int Document::loanDays() const { return 7; }    // mac dinh
int Book::loanDays()     const { return 14; }
int Magazine::loanDays() const { return 3; }
int Disc::loanDays()     const { return 2; }

Bây giờ nơi gọi không cần biết nó đang cầm loại gì:

cpp
LoanDate today(28, 12, 2026);
for (int i = 0; i < 3; i++) {
    LoanDate due = today + ds[i]->loanDays();
    cout << ds[i]->getTitle() << ": han tra " << due << endl;
}
text
Lap trinh huong doi tuong: han tra 11/01/2027
Vat ly Ngay nay: han tra 31/12/2026
Thi nghiem quang hoc: han tra 30/12/2026

Vì sao đây mới là điểm mấu chốt

Không có đa hình, dòng trên phải viết thành một chuỗi if: “nếu là sách thì 14, nếu là tạp chí thì 3…”. Thêm loại tài liệu mới là phải đi tìm và sửa mọi chuỗi if như vậy trong chương trình.

Có đa hình, thêm loại mới chỉ là viết thêm một lớp. Không đụng vào dòng nào đã chạy. Chương 6 sẽ kiểm chứng đúng điều này.

5.5 Destructor ảo — một dòng, tránh rò rỉ bộ nhớ ​

Khi bạn viết delete p; với p là Document* đang trỏ tới một Book, C++ cũng chọn destructor theo đúng quy tắc cũ: nếu destructor lớp cha không virtual thì chỉ destructor lớp cha chạy. Phần riêng của Book không được dọn.

cpp
class Document {
public:
    virtual ~Document();       // luon virtual khi lop co ham ao
};

Có virtual — chạy đủ hai destructor, đúng thứ tự con trước cha sau:

text
  (huy Book S001)
  (huy Document S001)

Bỏ virtual — chỉ còn một dòng, phần của Book bị bỏ quên:

text
  (huy Document S001)

Quy tắc thuộc lòng: lớp nào có một hàm virtual thì phải có destructor virtual. Không có ngoại lệ.

5.6 Nạp chồng toán tử ​

Hệ thống thư viện cần tính ngày trả. Ta viết lớp LoanDate và dạy cho nó hiểu các phép toán quen thuộc:

cpp
class LoanDate {
private:
    int day, month, year;
    void nextDay();                  // tien 1 ngay, tu xu ly sang thang

public:
    LoanDate(int d, int m, int y);

    LoanDate operator+(int days) const;               // ngay muon + so ngay
    int      operator-(const LoanDate& other) const;  // khoang cach 2 moc

    friend std::ostream& operator<<(std::ostream& os, const LoanDate& d);
};

Vì sao operator<< phải là friend ​

Khi bạn viết cout << d, toán hạng bên trái là cout chứ không phải đối tượng của bạn. Một phương thức thành viên luôn lấy đối tượng của chính nó làm toán hạng trái, nên không viết được kiểu này. Giải pháp: hàm tự do, và cho nó làm friend để chạm được vào phần private.

cpp
ostream& operator<<(ostream& os, const LoanDate& d) {
    if (d.day < 10)   os << '0';
    os << d.day << '/';
    if (d.month < 10) os << '0';
    os << d.month << '/' << d.year;
    return os;                   // tra ve os de con noi tiep cout << a << b
}

Ba điều dễ quên khi nạp chồng toán tử

operator+ phải có const và trả về một đối tượng mới — nó không được sửa đối tượng gốc. a + b không làm thay đổi a.

operator<< phải trả về ostream& (tham chiếu). Trả về void thì cout << a << b không biên dịch được.

Tham số nhận vào nên là const LoanDate& — tham chiếu hằng, tránh sao chép thừa và tránh sửa nhầm.

5.7 Làm theo từng bước: bật đa hình cho cây kế thừa ​

Sơ đồ vẫn là ba hộp của chương 4, nhưng hai phương thức ở lớp cha giờ có chữ {virtual}. Đó là toàn bộ khác biệt — và nó đáng 2 điểm ở mọi đề thi.

Bước 1. Chép thư mục, rồi chạy thử để thấy vấn đề trước khi sửa ​

sh
xcopy C:\OOP\uml3 C:\OOP\uml4\ /E /I
cd C:\OOP\uml4

Thêm ba dòng này vào cuối main.cpp, biên dịch, chạy:

cpp
Book b("S001", "Lap trinh huong doi tuong", 2019, 2, "Bjarne Stroustrup", 350);
Document* p = &b;
p->display();

Bạn sẽ thấy (và đây là kết quả SAI):

text
[TL] S001 | Lap trinh huong doi tuong | 2019 | Con 2 ban

In ra [TL] của lớp cha, dù đối tượng rõ ràng là một Book. Giữ nguyên màn hình này để lát nữa so.

Bước 2. Thêm virtual ở lớp cha ​

Trong Document.h, thêm đúng một từ vào đầu hai dòng:

cpp
    virtual void display() const;
    virtual int  loanDays() const;

Bước 3. Thêm override ở lớp con — và cố ý gõ sai một lần ​

Trong Book.h, gõ thiếu const để xem override làm việc:

cpp
    void display() override;      // co y thieu const

Nếu hiện ra lỗi này:

text
Book.h:14:10: error: 'void Book::display()' marked 'override',
               but does not override
   14 |     void display() override;
      |          ^~~~~~~

Vì sao bước này quan trọng

Nếu không viết override, dòng sai trên vẫn biên dịch sạch. Trình biên dịch coi đó là một hàm mới, khác hẳn, và đa hình lặng lẽ không hoạt động. Bạn sẽ ngồi dò cả buổi mà không hiểu vì sao vẫn in ra [TL].

Kết luận: luôn viết override ở mọi hàm ghi đè. Nó không bắt buộc về cú pháp, nhưng nó là cái bẫy chuột đặt sẵn cho chính bạn.

Sửa lại thành void display() const override; rồi làm tương tự cho loanDays() và cho Magazine.

Bước 4. Chạy lại đúng đoạn code của bước 1 — không sửa main ​

sh
g++ -std=c++17 -Wall *.cpp -o main.exe
main.exe

Bạn sẽ thấy:

text
[SACH] S001 | Lap trinh huong doi tuong | Bjarne Stroustrup | 2019 | 350 trang | Con 2 ban

So với màn hình ở bước 1. Một từ khoá, kết quả đổi hẳn — và bạn không phải sửa dòng nào trong main. Đó chính là tính đa hình.

Bước 5. Cho loanDays() trả về giá trị khác nhau theo từng loại ​

text
int Document::loanDays() const { return 7; }
int Book::loanDays()     const { return 14; }
int Magazine::loanDays() const { return 3; }

Bước 6. Viết vòng lặp đa hình — khuôn mẫu của mọi đề thi ​

cpp
Document* ds[3];
ds[0] = new Book("S001", "Lap trinh HDT", 2019, 2, "Stroustrup", 350);
ds[1] = new Magazine("TC001", "Vat ly Ngay nay", 2024, 4, 57, 9);
ds[2] = new Book("S002", "Vat ly dai cuong 1", 2021, 1, "Halliday", 520);

for (int i = 0; i < 3; i++) {
    ds[i]->display();
    cout << "   -> cho muon " << ds[i]->loanDays() << " ngay" << endl;
}
for (int i = 0; i < 3; i++) delete ds[i];

Bước 7. Thêm destructor ảo và nhìn thứ tự huỷ ​

Thêm virtual ~Document(); và ~Book() override;, mỗi cái in một dòng. Chạy, ghi lại. Rồi bỏ chữ virtual ở destructor lớp cha, chạy lại, ghi lại.

Có virtual:

text
  (huy Book S001)
  (huy Document S001)

Bỏ virtual — destructor của Book không chạy:

text
  (huy Document S001)

Quy tắc thuộc lòng: lớp nào có một hàm virtual thì phải có destructor virtual. Trả lại virtual trước khi đi tiếp.

Tự kiểm tra ​

40 phút, đóng sách.

  1. Thêm virtual cho display() ở Document, thêm override ở Book và Magazine. Chạy lại đoạn của mục 4.6 và xác nhận kết quả đã đổi.
  2. Thêm virtual int loanDays() const: mặc định 7, sách 14, tạp chí 3. Tạo mảng Document* ba phần tử và in hạn mượn của từng cái.
  3. Cố ý gõ void display() override ở lớp con (thiếu const). Ghi lại thông báo lỗi — đây là lý do luôn viết override.
  4. Viết lớp LoanDate với ba toán tử +, -, <<. Kiểm tra: 28/12/2026 + 14 phải ra 11/01/2027 (tháng 12 có 31 ngày).
  5. Thêm destructor có cout cho cả Document và Book. Chạy với virtual, ghi kết quả; bỏ virtual, chạy lại, ghi kết quả. Giải thích khác biệt bằng một câu.
