Xử lý ngoại lệ ​

Chương này ăn điểm ở đâu trong đề thi

  • Bắt và xử lý đúng ngoại lệ1 điểm, có ở 8/12 đề
  • Chương trình chạy đúng, test case hợp lý2 – 3 điểm — chương trình crash là mất trắng mục này

7.1 Vấn đề với cách báo lỗi hiện tại ​

Đến giờ, khi hết bản sách, Document::borrow() trả về false và Library::lend() tự in "Het ban: ...". Cách đó có hai chỗ hỏng:

  1. Lớp quản lý sách lại đang quyết định giao diện người dùng. In ra cái gì, in tiếng Việt hay tiếng Anh, in ra màn hình hay ghi vào file — đó không phải việc của một lớp tài liệu.
  2. Kiểu bool không mang theo thông tin. Mượn thất bại vì hết bản, vì sai mã, hay vì quá hạn mức? Nơi gọi không phân biệt được.

Ngoại lệ tách hai việc vốn khác nhau: nơi phát hiện lỗi chỉ việc ném ra kèm mô tả; nơi gọi quyết định làm gì với nó.

7.2 throw, try, catch ​

cpp
#include <stdexcept>

void Document::setYear(int newYear) {
    if (newYear < 1900 || newYear > 2026)
        throw invalid_argument("Nam xuat ban khong hop le: " + to_string(newYear));
    year = newYear;
}

Sau throw, những dòng phía dưới không chạy nữa — không cần return. Chương trình nhảy ngược lên trên theo chuỗi lời gọi, tìm khối catch đầu tiên hợp kiểu.

cpp
try {
    lib.get("S001").setYear(2030);
} catch (const invalid_argument& e) {
    cout << "  [Du lieu sai] " << e.what() << endl;
}
text
  [Du lieu sai] Nam xuat ban khong hop le: 2030
  • e.what() trả về đúng chuỗi bạn đưa vào lúc throw.
  • Luôn bắt bằng const ...& — tham chiếu hằng. Bắt bằng giá trị sẽ sao chép và có thể cắt mất phần lớp con (object slicing, mục 5.3).

7.3 Bốn loại ngoại lệ chuẩn hay dùng ​

LoạiDùng khiTrong hệ thống thư viện
invalid_argumentTham số truyền vào vô nghĩasetYear(3025)
out_of_rangeTìm một thứ không tồn tạimã tài liệu không có trong kho
overflow_errorVượt quá giới hạn cho phépmượn quá hạn mức
runtime_errorLỗi chung lúc chạylớp cha cho ngoại lệ tự định nghĩa

Tất cả đều nằm trong <stdexcept> và đều kế thừa từ std::exception. Điều đó quan trọng ở mục 7.5.

7.4 Ngoại lệ tự định nghĩa ​

Khi tình huống là chuyện riêng của nghiệp vụ mà không loại chuẩn nào tả đúng, hãy tự viết. Kế thừa runtime_error để dùng lại sẵn what():

cpp
#ifndef LIBRARYERROR_H
#define LIBRARYERROR_H

#include <stdexcept>
#include <string>

class OutOfCopies : public std::runtime_error {
public:
    explicit OutOfCopies(const std::string& title)
        : std::runtime_error("Het ban tren ke: " + title) {}
};

#endif

Chỉ có vậy: một constructor chuyển tiếp chuỗi mô tả lên lớp cha. Giờ borrow() không cần trả bool nữa:

cpp
void Document::borrow() {
    if (copies <= 0)
        throw OutOfCopies(title);
    copies--;
}

7.5 Nhiều nhánh catch — và thứ tự của chúng ​

Đây là khuôn mẫu đề thi hay hỏi nhất. Đọc kỹ ba dòng trong khối try:

cpp
for (const char* id : yeuCau) {
    cout << "  Yeu cau " << id << ": ";
    try {
        sv.checkQuota(dangMuon);       // 1. con han muc khong?
        Document& d = lib.get(id);     // 2. co tai lieu do khong?
        d.borrow();                    // 3. con ban tren ke khong?

        dangMuon++;
        cout << "OK - " << d.getTitle() << endl;
    }
    catch (const OutOfCopies& e)    { cout << "[Het ban]  " << e.what() << endl; }
    catch (const out_of_range& e)   { cout << "[Khong co] " << e.what() << endl; }
    catch (const overflow_error& e) { cout << "[Han muc]  " << e.what() << endl; }
    catch (const exception& e)      { cout << "[Loi khac] " << e.what() << endl; }
}

Ba dòng trong try đọc thẳng như mô tả nghiệp vụ, không còn if lồng nhau. Và một yêu cầu hỏng không làm dừng vòng lặp — các yêu cầu sau vẫn chạy.

Thứ tự catch: cụ thể trước, tổng quát sau

Các catch được thử theo thứ tự viết, và nhánh đầu tiên hợp kiểu sẽ thắng. Vì mọi ngoại lệ chuẩn đều kế thừa std::exception, nếu bạn đặt catch (const exception&) lên đầu thì nó nuốt hết — ba nhánh dưới không bao giờ chạy, và trình biên dịch không báo lỗi gì cả.

Hãy tự thử một lần: đảo nhánh tổng quát lên đầu, chạy lại, xem output đổi thế nào. Thử một lần thì nhớ cả đời.

Nhánh catch (const exception&) cuối cùng nên luôn có — nó là lưới an toàn cho những lỗi bạn chưa lường.

Kết quả chạy đầy đủ:

text
  Yeu cau S001: OK - Lap trinh huong doi tuong
  Yeu cau D001: OK - Thi nghiem quang hoc
  Yeu cau D001: [Het ban]  Het ban tren ke: Thi nghiem quang hoc
  Yeu cau S999: [Khong co] Khong co tai lieu ma S999
  Yeu cau TC001: OK - Vat ly Ngay nay
  Yeu cau LV001: OK - Mang nano TiO2
  Yeu cau S002: OK - Vat ly dai cuong 1
  Yeu cau TC001: [Han muc]  Vuot han muc 5 tai lieu cua Tran Thi Binh
Chuong trinh ket thuc binh thuong.

Dòng cuối là điều đáng nói: chương trình gặp bốn lỗi khác nhau mà vẫn kết thúc bình thường, không crash. Đó là toàn bộ mục đích của xử lý ngoại lệ — và cũng là lý do nó đáng 1 điểm trong 8/12 đề thi.

7.6 Ném ở đâu, bắt ở đâu ​

Quy tắc

Ném ở chỗ phát hiện ra vấn đề — sâu trong lớp, nơi biết rõ chuyện gì sai.

Bắt ở chỗ biết phải làm gì — thường là main, nơi biết đang phục vụ ai và nên in gì cho họ.

Giữa hai chỗ đó, các hàm trung gian không cần làm gì cả. Ngoại lệ tự đi qua chúng. Đó là điểm mạnh lớn nhất so với việc trả về mã lỗi rồi chuyền tay nhau.

Đừng bắt rồi nuốt im lặng. Khối catch rỗng là cách chắc chắn nhất để có một chương trình chạy sai mà không ai biết:

text
catch (const exception& e) { }     // dung bao gio lam vay

7.7 Làm theo từng bước: thay báo lỗi bằng ngoại lệ ​

Sơ đồ chỉ thêm một hộp — lớp ngoại lệ tự định nghĩa — nhưng ba lớp cũ đổi chữ ký:

Dòng throws ... trên UML không phải cú pháp C++ — nó là ghi chú cho biết hàm đó ném ngoại lệ gì. Trong code, nó thành một câu lệnh throw bên trong thân hàm.

Bước 1. Chép thư mục, thêm #include <stdexcept> ​

sh
xcopy C:\OOP\uml5 C:\OOP\uml6\ /E /I
cd C:\OOP\uml6

Thêm #include <stdexcept> vào đầu Document.cpp, Library.cpp, Reader.cpp và main.cpp.

Bước 2. Đổi setter sang ném ngoại lệ ​

Bỏ cả khối cout và return, thay bằng một dòng:

cpp
void Document::setYear(int newYear) {
    if (newYear < 1900 || newYear > 2026)
        throw invalid_argument("Nam xuat ban khong hop le: " + to_string(newYear));
    year = newYear;
}

Biên dịch và chạy thử ngay khi chưa có try/catch nào:

Chương trình sẽ chết ngang:

text
terminate called after throwing an instance of 'std::invalid_argument'
  what():  Nam xuat ban khong hop le: 3025

Đó là điều đúng. Ngoại lệ không được bắt thì chương trình dừng — đây là cách C++ nói “có chuyện nghiêm trọng mà không ai xử lý”. Bước 3 sẽ bắt nó.

Bước 3. Bọc lời gọi trong try/catch ​

cpp
try {
    lib.get("S001").setYear(2030);
} catch (const invalid_argument& e) {
    cout << "  [Du lieu sai] " << e.what() << endl;
}

Bạn sẽ thấy:

text
  [Du lieu sai] Nam xuat ban khong hop le: 3025

Chương trình không chết nữa, và e.what() trả về đúng chuỗi bạn đưa vào lúc throw.

Bước 4. Tạo file LibraryError.h cho ngoại lệ riêng ​

cpp
#ifndef LIBRARYERROR_H
#define LIBRARYERROR_H

#include <stdexcept>
#include <string>

class OutOfCopies : public std::runtime_error {
public:
    explicit OutOfCopies(const std::string& title)
        : std::runtime_error("Het ban tren ke: " + title) {}
};

#endif

Chỉ có vậy: một constructor chuyển tiếp chuỗi mô tả lên lớp cha, để dùng lại sẵn what().

Bước 5. Đổi borrow() từ bool sang void ​

cpp
void Document::borrow() {
    if (copies <= 0)
        throw OutOfCopies(title);
    copies--;
}

Biên dịch sẽ báo lỗi ở mọi chỗ đang dùng if (d->borrow()). Đó là tin tốt: trình biên dịch đang dẫn bạn đi sửa đủ mọi nơi, không sót chỗ nào.

Bước 6. Thêm Library::get() và Reader::checkQuota() ​

cpp
Document& Library::get(const string& id) const {
    Document* d = findById(id);
    if (d == nullptr)
        throw out_of_range("Khong co tai lieu ma " + id);
    return *d;
}

void Reader::checkQuota(int borrowingNow) const {
    if (borrowingNow >= maxBorrow())
        throw overflow_error("Vuot han muc " + to_string(maxBorrow()) +
                             " tai lieu cua " + fullName);
}

Bước 7. Gom xử lý về một vòng try/catch bốn nhánh ​

cpp
const char* yeuCau[] = {"S001", "D001", "D001", "S999",

for (const char* id : yeuCau) {
    cout << "  Yeu cau " << id << ": ";

    catch (const overflow_error& e) { cout << "[Han muc]  " << e.what() << endl; }
    catch (const exception& e)      { cout << "[Loi khac] " << e.what() << endl; }
}

Bước 8. Cố ý đảo thứ tự catch ​

Chuyển nhánh catch (const exception& e) lên đầu tiên, biên dịch, chạy lại:

Ba nhánh cụ thể không bao giờ chạy nữa:

text
  Yeu cau D001: [Loi khac] Het ban tren ke: Thi nghiem quang hoc
  Yeu cau S999: [Loi khac] Khong co tai lieu ma S999
  Yeu cau TC001: [Loi khac] Vuot han muc 5 tai lieu cua Tran Thi Binh

Không có lỗi biên dịch, không có cảnh báo — chỉ có ba nhánh code chết lặng lẽ. Vì mọi ngoại lệ chuẩn đều kế thừa std::exception, nhánh tổng quát nuốt hết. Cụ thể trước, tổng quát sau. Trả lại thứ tự cũ trước khi đi tiếp.

Tự kiểm tra ​

40 phút, đóng sách.

  1. Đổi setYear và setTitle sang ném invalid_argument.
  2. Viết LibraryError.h với lớp OutOfCopies kế thừa runtime_error. Đổi borrow() từ bool sang void và ném ngoại lệ này.
  3. Thêm Library::get(id) ném out_of_range, và Reader::checkQuota(n) ném overflow_error.
  4. Viết vòng lặp try/catch bốn nhánh như mục 7.5, chạy với danh sách yêu cầu để kích hoạt đủ cả bốn tình huống.
  5. Chuyển catch (const exception&) lên đầu, chạy lại, ghi lại output. Giải thích bằng một câu.

Bài nâng cao — hay ra trong đề

Viết Library::napTuFile(const string& tenFile): đọc danh mục từ file văn bản, mỗi dòng một tài liệu.

File không mở được → ném runtime_error. Một dòng sai định dạng → bỏ qua dòng đó, in cảnh báo, đọc tiếp. Đọc xong in tổng số dòng đọc được và số dòng lỗi.

Đây là tình huống thật hay gặp nhất: một dòng hỏng không được phép làm hỏng cả lần nhập.
