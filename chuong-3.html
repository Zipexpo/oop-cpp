Chương 3

Tính đóng gói ​

Chương này ăn điểm ở đâu trong đề thi

  • Tính đóng gói (private/protected + getter/setter)1 điểm, có ở 4/12 đề
  • Thiết kế đúng lớp2 điểm — thiết kế sai mức truy cập là thiết kế sai

3.1 Vấn đề ​

Chương 2 để mọi thuộc tính public. Nghĩa là bất kỳ dòng nào trong chương trình cũng làm được việc này:

cpp
Document d("TL001", "Lap trinh huong doi tuong", 2019);

d.year = 3025;        // nam xuat ban o tuong lai
d.title = "";         // tua de rong
d.copies = -7;        // am bay ban sach

Trình biên dịch không phản đối gì cả, chương trình vẫn chạy, và bạn có một cuốn sách xuất bản năm 3025 với âm bảy bản. Khi lỗi lộ ra ở chỗ khác, bạn phải đi tìm mọi dòng trong chương trình có thể đã gán vào year.

Đóng gói trả lời đúng vấn đề đó: đóng dữ liệu lại, và chỉ mở đúng một cửa để ra vào. Khi chỉ có một cửa, bạn đặt người gác ở đó là xong.

3.2 Ba mức truy cập ​

Từ khoáAi chạm đượcDùng cho
privateChỉ code bên trong chính lớp đóMặc định cho mọi thuộc tính
protectedLớp đó và các lớp con của nóThuộc tính mà lớp con cần dùng (chương 4)
publicBất kỳ đâuCác phương thức mà bên ngoài cần gọi

Quy tắc mặc định

Thuộc tính: private (hoặc protected nếu có lớp con cần tới).

Phương thức: public nếu bên ngoài phải gọi, private nếu chỉ là hàm phụ dùng nội bộ.

Nếu phân vân, đóng lại trước. Mở ra sau này rất dễ; đóng lại sau khi cả chương trình đã dùng thì rất khó.

3.3 Getter và setter ​

Đóng dữ liệu lại rồi thì bên ngoài đọc bằng gì? Bằng getter — hàm chỉ đọc, luôn có const:

cpp
std::string getTitle() const;
int         getYear() const;
int         getCopies() const;

Và ghi bằng setter. Setter mới là chỗ có giá trị thật — nó là nơi duy nhất dữ liệu thay đổi được, nên cũng là nơi duy nhất cần đặt luật:

cpp
void Document::setYear(int newYear) {
    if (newYear < 1900 || newYear > 2026) {
        cout << "  ! Nam " << newYear << " khong hop le. Giu nguyen "
             << year << "." << endl;
        return;
    }
    year = newYear;
}

Bây giờ d.setYear(3025) bị từ chối, và bị từ chối ở một chỗ duy nhất trong toàn chương trình. Ở chương 7 ta sẽ thay dòng cout này bằng một ngoại lệ — nhưng ý tưởng không đổi.

Đừng viết getter/setter cho mọi thứ

Một lỗi rất phổ biến: đóng hết thuộc tính rồi viết đủ cặp get/set cho từng cái. Kết quả là dữ liệu vẫn mở toang, chỉ dài dòng hơn.

Hỏi trước khi viết: bên ngoài có thật sự cần sửa cái này không? Mã tài liệu id thì không — cấp một lần lúc tạo rồi thôi, nên chỉ cần getId(), không cần setId().

3.4 Phương thức nghiệp vụ tốt hơn setter ​

Số bản còn trên kệ thay đổi khi có người mượn hoặc trả. Bạn có thể viết setCopies(int) rồi để nơi gọi tự tính, nhưng như vậy luật nghiệp vụ lại rò ra ngoài. Cách tốt hơn là đặt tên theo đúng việc đang xảy ra:

cpp
bool Document::borrow() {
    if (copies <= 0) return false;   // het ban, khong cho muon
    copies--;
    return true;
}

void Document::giveBack() {
    copies++;
}

bool Document::available() const {
    return copies > 0;
}

So sánh hai cách viết ở nơi gọi:

Dùng setterDùng phương thức nghiệp vụ
if (d.getCopies() > 0)
    d.setCopies(d.getCopies() - 1);		d.borrow();
Luật “còn bản mới cho mượn” nằm ở nơi gọi — và phải lặp lại ở mọi nơi gọiLuật nằm trong lớp, không ai quên được

3.5 Cấp phát động: new và delete ​

Phần này bài giảng chưa phủ

Tám tuần slide lý thuyết không có new / delete (tuần 7 chỉ nhắc chữ “delete operator” khi nói về destructor ảo). Nhưng mọi đề thi đều dùng — new Car(...) rồi bỏ vào danh sách. Nên phải học ở đây.

Mọi biến bạn khai báo từ trước tới giờ đều tự sinh ra và tự biến mất theo khối lệnh chứa nó:

cpp
void f() {
    Document d("TL001", "Sach", 2019, 2);   // sinh ra o day
}                                            // tu bien mat o day

Nhưng thư viện cần giữ tài liệu lâu hơn khối lệnh tạo ra nó, và số lượng thì chưa biết trước lúc viết code. Hai việc đó cần bộ nhớ cấp phát động — bạn tự xin, và tự trả.

ViệcCú phápKết quả
Xin một đối tượngnew Document("TL001", "Sach", 2019, 2)Trả về Document*
Trả lại một đối tượngdelete d;Gọi destructor rồi thu hồi bộ nhớ
Xin một mảngnew int[n]Trả về int*
Trả lại một mảngdelete[] a;Chú ý cặp ngoặc vuông
cpp
Document* d = new Document("TL001", "Lap trinh huong doi tuong", 2019, 2);

d->display();        // con tro thi dung ->, khong dung .

delete d;            // tra lai, neu khong thi ro ri bo nho

Bốn luật, thuộc lòng bốn luật này là đủ cho cả môn

1. Xin bằng gì thì trả bằng nấy. new đi với delete; new[] đi với delete[]. Lẫn lộn là hỏng, và thường không báo lỗi gì.

2. Xin ở đâu thì nhớ trả ở đó. Trong một lớp, thường là: xin ở constructor, trả ở destructor.

3. Trả đúng một lần. delete hai lần trên cùng một con trỏ làm chương trình chết ngay.

4. Con trỏ dùng ->, đối tượng dùng . Đây là chỗ nhầm nhiều nhất khi mới chuyển sang dùng con trỏ.

Mảng con trỏ — hai ngôi sao và vì sao cần chúng ​

Thư viện cần giữ nhiều tài liệu. Nếu giữ Document* items thì đó là một con trỏ tới một tài liệu, hoặc tới một mảng Document — mà mảng Document thì không chứa được Book hay Magazine ở chương sau (lý do ở mục 5.3).

Nên ta giữ một mảng các con trỏ:

cpp
Document** items;                      // mang cac con tro Document*

items = new Document*[capacity];       // xin cho chua 'capacity' con tro

items[0] = new Document("TL001", "Sach", 2019, 2);   // xin tung tai lieu
items[1] = new Document("TL002", "Tap chi", 2021, 1);

Đọc hai ngôi sao thế nào

Document* = địa chỉ của một tài liệu.

Document** = địa chỉ của một dãy các địa chỉ đó.

Cách nhớ: mỗi ngôi sao là một lần “địa chỉ của”. Bạn chỉ cần tới hai sao trong cả môn này, và chỉ ở đúng một chỗ — mảng chứa của lớp quản lý.

Vì thế cũng phải trả hai lần, đúng thứ tự: xoá từng tài liệu trước, xoá mảng chứa sau. Mục 3.6 làm đúng việc đó.

3.6 Lớp chứa lớp khác: Library ​

Một thư viện giữ nhiều tài liệu. Vì số lượng chưa biết trước, ta cấp phát động một mảng con trỏ:

cpp
class Library {
private:
    std::string name;
    std::string address;
    Document** items;     // mang con tro, cap phat dong
    int count;            // so tai lieu hien co
    int capacity;         // suc chua toi da

public:
    Library(const std::string& name, const std::string& address, int capacity);
    ~Library();

    bool add(Document* d);
    Document* findById(const std::string& id) const;
    void lend(const std::string& id);
    void receive(const std::string& id);
    void listAll() const;
};

Xin bộ nhớ ở constructor, trả lại ở destructor ​

cpp
Library::Library(const string& name, const string& address, int capacity)
    : name(name), address(address), count(0), capacity(capacity) {
    items = new Document*[capacity];
}

Library::~Library() {
    for (int i = 0; i < count; i++)
        delete items[i];       // xoa tung tai lieu
    delete[] items;            // roi moi xoa mang chua con tro
    cout << "(Da dong cua thu vien " << name << ")" << endl;
}

Hai dòng delete, đúng thứ tự đó

delete[] items chỉ xoá cái mảng chứa con trỏ, không xoá các đối tượng mà con trỏ đang trỏ tới. Xoá mảng trước thì bạn mất luôn địa chỉ và không còn cách nào xoá các tài liệu — rò rỉ bộ nhớ.

Dòng cout trong destructor không bắt buộc, nhưng lúc học nên có: nó là bằng chứng nhìn thấy được rằng destructor đã chạy. Khi nộp bài thi thì bỏ đi cho output sạch.

Ba tình huống của một lượt mượn ​

cpp
void Library::lend(const string& id) {
    Document* d = findById(id);

    if (d == nullptr) {
        cout << "Khong tim thay ma " << id << "!" << endl;
        return;
    }
    if (d->borrow())
        cout << "Da cho muon: " << d->getTitle()
             << " (con " << d->getCopies() << " ban)" << endl;
    else
        cout << "Het ban: " << d->getTitle() << endl;
}

Ba nhánh — không có mã, có mã nhưng hết bản, cho mượn được — là khuôn mẫu lặp lại trong hầu hết đề thi. Nhớ kỹ dạng này.

Kết quả chạy:

text
--- Thu vien Khoa - Nha I - Lau 1 ---
[TL] TL001 | Lap trinh huong doi tuong | 2019 | Con 2 ban
[TL] TL002 | Vat ly dai cuong 1 | 2021 | Con 1 ban
--- MUON TRA ---
Da cho muon: Lap trinh huong doi tuong (con 1 ban)
Da cho muon: Lap trinh huong doi tuong (con 0 ban)
Het ban: Lap trinh huong doi tuong
Khong tim thay ma TL999!
Da nhan tra: Lap trinh huong doi tuong (con 1 ban)

3.7 Mũi tên chấm và mũi tên móc ​

Hai ký hiệu này làm nhiều người lẫn, và lẫn thì không biên dịch được:

ViếtKhi nàoVí dụ

p->display() chỉ là cách viết gọn của (*p).display(). Từ chương 5 trở đi bạn sẽ dùng -> gần như liên tục, vì đa hình chỉ hoạt động qua con trỏ.

3.8 Làm theo từng bước: đóng gói lớp Document ​

Sơ đồ sau là lớp Document của chương 2 sau khi đóng gói. So với sơ đồ ở mục 2.6, tầng thuộc tính có thêm copies, còn tầng phương thức dài thêm: getter, setter có kiểm tra dữ liệu và ba phương thức nghiệp vụ.

Bước 1. Chép thư mục chương trước sang thư mục mới ​

sh
xcopy C:\OOP\uml1 C:\OOP\uml2\ /E /I
cd C:\OOP\uml2

Từ đây tới hết sách, mỗi chương đều bắt đầu bằng bước này. Không làm lại từ đầu. Việc mở rộng code cũ chính là thứ đang được luyện.

Bước 2. Đổi public thành private, rồi biên dịch để thấy chuyện gì xảy ra ​

Trong Document.h, đổi nhãn của tầng thuộc tính thành private:. Rồi thêm vào main.cpp một dòng cố ý sai:

cpp
    cout << d1.title << endl;   // truy cap thang vao thuoc tinh
sh
g++ -std=c++17 -Wall *.cpp -o main.exe

Nếu hiện ra lỗi này:

text
main.cpp:6:15: error: 'std::string Document::title' is private within this context
    6 |     cout << d.title << endl;
      |               ^~~~~
In file included from main.cpp:1:
Document.h:7:17: note: declared private here
    7 |     std::string title;
      |                 ^~~~~

Đây chính là tính đóng gói đang làm việc. Trình biên dịch vừa chặn một đường vào dữ liệu. Ghi lại thông báo này rồi xoá dòng vừa thêm.

Bước 3. Thêm thuộc tính copies và bốn getter ​

cpp
    std::string getId() const;
    std::string getTitle() const;
    int getYear() const;
    int getCopies() const;

Cài đặt trong .cpp gọn một dòng mỗi hàm:

text
string Document::getId() const    { return id; }
string Document::getTitle() const { return title; }
int    Document::getYear() const  { return year; }
int    Document::getCopies() const { return copies; }

Bước 4. Sửa main.cpp để dùng getter thay vì truy cập thẳng ​

cpp
    cout << d1.getTitle() << endl;

Biên dịch lại — lần này phải sạch. Đây là cách duy nhất bên ngoài đọc được dữ liệu từ giờ trở đi.

Bước 5. Thêm hai setter có kiểm tra ​

cpp

Bước 7. Thêm lớp Library — hộp thứ hai trên sơ đồ ​

Quan hệ giữa Library và Document là kim cương rỗng (một thư viện chứa nhiều tài liệu), nên theo bảng dịch ở mục 2.5, nó thành một thuộc tính mảng con trỏ:

cpp
    Document** items;     // <- kim cuong rong 1 --- * tren UML
    int count;
    int capacity;
}

Tạo Library.h và Library.cpp theo đúng tám bước của mục 2.6. Constructor cấp phát, destructor trả lại:

cpp
Library::Library(const string& name, const string& address, int capacity)
    : name(name), address(address), count(0), capacity(capacity) {
    items = new Document*[capacity];
}

Library::~Library() {
    for (int i = 0; i < count; i++) delete items[i];
    delete[] items;
    cout << "(Da dong cua thu vien " << name << ")" << endl;
}

Tự kiểm tra ​

30 phút, đóng sách.

  1. Lấy lớp Document của chương 2, chuyển hết thuộc tính sang private. Biên dịch. Ghi lại thông báo lỗi mà main.cpp nhận được — đó chính là tính đóng gói đang làm việc.
  2. Thêm copies, các getter, và setYear có kiểm tra khoảng [1900, 2026].
  3. Thêm ba phương thức nghiệp vụ available(), borrow(), giveBack().
  4. Viết lớp Library giữ mảng con trỏ động, có destructor trả lại bộ nhớ, và lend() xử lý đủ ba tình huống.
  5. Chạy kịch bản: 2 tài liệu, mượn tài liệu đầu ba lần, mượn một mã không tồn tại, trả lại một bản. Output phải khớp với khối ở mục 3.5.
