Tuần 5 — Tính đóng gói ​

Tuần này thêm vào hệ thống thư viện: đóng kín dữ liệu của Document, thêm số bản còn trên kệ, và dựng lớp Library quản lý một mảng con trỏ Document*.

Mang gì từ tuần trước ​

Chép nguyên thư mục <MSSV>_w04/ thành <MSSV>_w05/ rồi sửa tiếp trên đó. Không tạo lại từ đầu.

Mục tiêu ​

  • Hiểu vì sao để dữ liệu public là nguy hiểm, và private + getter/setter giải quyết gì.
  • Đặt luật kiểm tra dữ liệu vào đúng một chỗ duy nhất (setter).
  • Quản lý một mảng con trỏ cấp phát động và giải phóng đúng cách trong destructor.

Lý thuyết cần nắm ​

Tuần này bạn khoá dữ liệu của Document lại và viết lớp Library giữ một mảng con trỏ. Ví dụ bên dưới vẫn dùng bài hát như tuần 4: lớp Song, thêm Album (đĩa nhạc trong kho) và Playlist (danh sách phát). Mọi đoạn code đều đã biên dịch và chạy thật. Đọc để nắm cách viết, rồi tự làm cho Document và Library.

1. Để public thì ai cũng sửa được, kể cả sửa sai ​

Lớp Song của tuần 4 để mọi thứ public. Không gì ngăn một dòng code trong main gán thời lượng âm:

cpp
#include <iostream>
#include <string>
using namespace std;

class Song {
public:
    string title;
    int seconds;

    void show() const {
        cout << title << " (" << seconds / 60 << " phut " << seconds % 60 << " giay)" << endl;
    }
};

int main() {
    Song s;
    s.title = "Hello Viet Nam";
    s.seconds = -50;                     // khong ai ngan duoc
    s.show();
    return 0;
}
text
Hello Viet Nam (0 phut -50 giay)

Chương trình biên dịch không một cảnh báo và vẫn chạy. Người viết lớp biết thời lượng phải lớn hơn 0, nhưng khi thuộc tính là public thì không có cách nào bắt mọi chỗ khác trong chương trình tuân theo. Dữ liệu hỏng ở main nhưng lộ ra ở show(); chương trình càng lớn, bạn càng dễ đi tìm lỗi sai chỗ.

2. private: g++ chặn ngay lúc biên dịch ​

Đưa thuộc tính xuống dưới private:. Thuộc tính private chỉ dùng được bên trong lớp, tức là trong constructor và các phương thức của chính lớp đó. main không gán được nữa, nên lớp cần constructor để nhận giá trị ban đầu:

cpp
#include <iostream>
#include <string>
using namespace std;

class Song {
private:
    string title;
    int seconds;

public:
    Song(const string& title, int seconds) : title(title), seconds(seconds) {}

    void show() const {
        cout << title << " (" << seconds / 60 << " phut " << seconds % 60 << " giay)" << endl;
    }
};

int main() {
    Song s("Hello Viet Nam", 263);
    s.seconds = -50;
    s.show();
    return 0;
}
text
main.cpp: In function 'int main()':
main.cpp:20:7: error: 'int Song::seconds' is private within this context
   20 |     s.seconds = -50;
      |       ^~~~~~~
main.cpp:8:9: note: declared private here
    8 |     int seconds;
      |         ^~~~~~~
  • Dòng error chỉ đúng chỗ vi phạm: dòng 20 nằm trong main, tức là bên ngoài lớp.
  • Dòng note: declared private here chỉ chỗ thuộc tính được khai báo.
  • Constructor và show() vẫn dùng title, seconds bình thường, vì chúng nằm bên trong lớp.
  • Xoá dòng s.seconds = -50; thì chương trình biên dịch lại được. private chỉ báo lỗi ở những dòng chạm thẳng vào thuộc tính từ bên ngoài; chỗ nào chỉ gọi constructor và phương thức thì không bị ảnh hưởng.

3. Getter và setter có kiểm tra ​

Muốn bên ngoài đọc được thì thêm getter. Muốn bên ngoài sửa được thì thêm setter, và setter là nơi kiểm tra dữ liệu trước khi nhận. Sơ đồ của Song sau khi đóng gói:

Thấy trên UMLViết trong file .h
Dấu - ở đầu dòngđặt dòng đó dưới private:
+ getTitle() : stringstd::string getTitle() const; (getter chỉ đọc nên có const)
+ setSeconds(int) : voidvoid setSeconds(int newSeconds); (setter sửa thuộc tính nên không có const)

Viết gọn trong một file:

cpp
#include <iostream>
#include <string>
using namespace std;

class Song {
private:
    string title;
    int seconds;

public:
    Song(const string& title, int seconds) : title(title), seconds(0) {
        setSeconds(seconds);             // dung lai luat kiem tra cua setter
    }

    string getTitle() const { return title; }
    int getSeconds() const { return seconds; }

    void setSeconds(int newSeconds) {
        if (newSeconds <= 0) {
            cout << "  -> Tu choi " << newSeconds << ", thoi luong van la " << seconds << " giay" << endl;
            return;
        }
        seconds = newSeconds;
    }

    void show() const {
        cout << title << " (" << seconds / 60 << " phut " << seconds % 60 << " giay)" << endl;
    }
};

int main() {
    Song s("Hello Viet Nam", 263);
    s.setSeconds(-50);
    s.show();
    s.setSeconds(300);
    s.show();
    cout << "Tua: " << s.getTitle() << ", dai " << s.getSeconds() << " giay" << endl;
    return 0;
}
text
  -> Tu choi -50, thoi luong van la 263 giay
Hello Viet Nam (4 phut 23 giay)
Hello Viet Nam (5 phut 0 giay)
Tua: Hello Viet Nam, dai 300 giay
  • Setter kiểm tra trước. Giá trị sai thì báo rồi return ngay, thuộc tính giữ nguyên giá trị cũ. Giá trị đúng mới gán.
  • Constructor gọi lại setSeconds thay vì tự kiểm tra thêm lần nữa, nên luật "thời lượng phải dương" chỉ nằm ở một chỗ. Danh sách khởi tạo đặt seconds(0) trước, để lỡ giá trị truyền vào bị từ chối thì thời lượng là 0 chứ không phải giá trị rác.
  • Không phải thuộc tính nào cũng cần setter. Song không có setTitle, vì tựa bài hát không đổi sau khi tạo.

4. Getter phải có const ​

Chữ const sau getter không chỉ để cho đẹp. Một hàm nhận const Song& chỉ được gọi những phương thức có const. Quên const ở getTitle:

cpp
#include <iostream>
#include <string>
using namespace std;

class Song {
private:
    string title;

public:
    Song(const string& title) : title(title) {}
    string getTitle() { return title; }          // quen const
};

void inTua(const Song& s) {
    cout << s.getTitle() << endl;
}

int main() {
    Song s("Hello Viet Nam");
    inTua(s);
    return 0;
}
text
main.cpp: In function 'void inTua(const Song&)':
main.cpp:15:23: error: passing 'const Song' as 'this' argument discards qualifiers [-fpermissive]
   15 |     cout << s.getTitle() << endl;
      |             ~~~~~~~~~~^~
main.cpp:11:12: note:   in call to 'std::string Song::getTitle()'
   11 |     string getTitle() { return title; }          // quen const
      |            ^~~~~~~~

discards qualifiers nghĩa là lời gọi này sẽ làm mất chữ const của s. g++ không cho, vì getTitle() không hứa là chỉ đọc. Thêm const sau getTitle() là hết lỗi. Thang điểm tuần này chấm riêng việc getter có const.

5. Hàm nghiệp vụ, và khi nào phải viết this-> ​

Nhiều thuộc tính không nên có setter kiểu "gán gì cũng được". Số đĩa trong kho chỉ thay đổi khi bán hoặc nhập thêm, nên lớp Album chỉ cho đúng hai thao tác đó:

cpp
#include <iostream>
#include <string>
using namespace std;

class Album {
private:
    string name;
    int stock;                           // so dia con trong kho

public:
    Album(const string& name, int stock) : name(name), stock(stock) {
        if (stock < 0) this->stock = 0;  // "stock" o day la tham so; this->stock moi la thuoc tinh
    }

    bool sell(int n) {                   // ban n dia neu du hang
        if (n <= 0 || n > stock) return false;
        stock -= n;
        return true;
    }

    void restock(int n) {
        if (n > 0) stock += n;
    }

    void show() const {
        cout << name << ": con " << stock << " dia" << endl;
    }
};

int main() {
    Album a("Mua xuan tren thanh pho", 5);
    cout << (a.sell(3) ? "Ban duoc 3 dia" : "Khong du hang") << endl;
    cout << (a.sell(4) ? "Ban duoc 4 dia" : "Khong du hang") << endl;
    a.restock(10);
    a.show();

    Album b("Dia loi", -7);
    b.show();
    return 0;
}
text
Ban duoc 3 dia
Khong du hang
Mua xuan tren thanh pho: con 12 dia
Dia loi: con 0 dia
  • sell kiểm tra trước; không đủ hàng thì trả false và không trừ. Người gọi dựa vào giá trị trả về để in thông báo phù hợp.
  • Không có setStock, nên từ bên ngoài lớp không có cách nào làm số đĩa âm.

Trong constructor, tham số stock trùng tên với thuộc tính stock. Trong thân hàm, chữ stock là tham số; muốn nói tới thuộc tính phải viết this->stock. Quên this->:

cpp
        if (stock < 0) stock = 0;        // SAI: sua tham so, thuoc tinh van am
text
Ban duoc 3 dia
Khong du hang
Mua xuan tren thanh pho: con 12 dia
Dia loi: con -7 dia

g++ không cảnh báo gì, vì gán cho một tham số int là việc hợp lệ. (Tuần 4, tham số là const string& nên câu title = title; bị báo lỗi; ở đây thì im lặng.) Trong danh sách khởi tạo thì không cần this->: với stock(stock), chữ ngoài ngoặc luôn là thuộc tính.

6. Mảng con trỏ cấp phát động ​

Playlist giữ nhiều bài hát, nhưng số chỗ tối đa chỉ biết lúc tạo danh sách. Vì vậy constructor xin một mảng con trỏ bằng new:

  • Song** songs; là một con trỏ tới ô đầu tiên của mảng; mỗi ô chứa một Song*.
  • songs = new Song*[capacity]; xin capacity ô con trỏ, chưa có bài hát nào. Ô chưa gán chứa giá trị rác, nên chỉ dùng các ô từ 0 tới count - 1.
  • Mỗi bài hát được tạo riêng bằng new Song(...), rồi đưa địa chỉ cho add.
cpp
#include <iostream>
#include <string>
using namespace std;

class Song {
private:
    string title;
    int seconds;

public:
    Song(const string& title, int seconds) : title(title), seconds(seconds) {}
    string getTitle() const { return title; }
    void show() const {
        cout << "  " << title << " (" << seconds / 60 << " phut " << seconds % 60 << " giay)" << endl;
    }
};

class Playlist {
private:
    string name;
    Song** songs;                        // mang cac con tro Song*
    int count;
    int capacity;

public:
    Playlist(const string& name, int capacity) : name(name), count(0), capacity(capacity) {
        songs = new Song*[capacity];     // xin cho chua 'capacity' con tro
    }

    ~Playlist() {
        for (int i = 0; i < count; i++)
            delete songs[i];             // tra tung bai hat
        delete[] songs;                  // roi tra mang con tro
        cout << "(Da xoa danh sach " << name << ")" << endl;
    }

    bool add(Song* s) {
        if (count >= capacity) return false;
        songs[count] = s;
        count++;
        return true;
    }

    Song* findByTitle(const string& title) const {
        for (int i = 0; i < count; i++)
            if (songs[i]->getTitle() == title)
                return songs[i];
        return nullptr;
    }

    void listAll() const {
        cout << "Danh sach " << name << ":" << endl;
        for (int i = 0; i < count; i++)
            songs[i]->show();            // songs[i] la con tro nen dung ->
    }
};

int main() {
    Playlist p("Di hoc", 2);
    p.add(new Song("Hello Viet Nam", 263));
    p.add(new Song("Mua he", 215));

    Song* thua = new Song("Bai thu ba", 200);
    if (!p.add(thua)) {
        cout << "Danh sach day, khong them duoc: " << thua->getTitle() << endl;
        delete thua;                     // khong vao danh sach thi tu tra bo nho
    }
    p.listAll();

    Song* s = p.findByTitle("Mua he");
    if (s != nullptr) cout << "Tim thay: " << s->getTitle() << endl;
    if (p.findByTitle("Khong co") == nullptr) cout << "Khong tim thay bai nay" << endl;
    return 0;
}
text
Danh sach day, khong them duoc: Bai thu ba
Danh sach Di hoc:
  Hello Viet Nam (4 phut 23 giay)
  Mua he (3 phut 35 giay)
Tim thay: Mua he
Khong tim thay bai nay
(Da xoa danh sach Di hoc)
  • songs[i] là một Song*, nên gọi phương thức bằng mũi tên: songs[i]->show().
  • findByTitle duyệt hết mảng; không thấy thì trả nullptr ở sau vòng lặp. Người gọi phải kiểm tra nullptr trước khi dùng kết quả.
  • add thành công thì từ đó Playlist chịu trách nhiệm trả bộ nhớ của bài hát. add thất bại thì bài hát không nằm trong danh sách, nên main phải tự delete thua;.

7. Destructor: trả lại đúng thứ đã xin ​

Destructor tên là dấu ~ cộng tên lớp, không tham số, không kiểu trả về, và tự chạy khi đối tượng bị huỷ. p là biến thường trong main, nên destructor của nó chạy lúc main kết thúc; dòng (Da xoa danh sach Di hoc) là bằng chứng.

Mỗi lần new phải có đúng một lần trả, và trả đúng kiểu:

Xin bằngTrả bằngTrong Playlist
new Song(...) (một đối tượng)deletedelete songs[i]; cho từng bài
new Song*[capacity] (một mảng)delete[]delete[] songs;

Thứ tự quan trọng: trả từng bài hát trước, trả mảng sau. Trả mảng trước thì mất luôn các con trỏ nằm trong đó, không còn cách nào trả các bài hát.

Hai lỗi sau không có triệu chứng gì khi chạy, nên phải tự đọc code để bắt:

  • Viết delete songs; thay cho delete[] songs;. g++ không cảnh báo và chương trình in ra y hệt, nhưng theo chuẩn C++ đây là lỗi: kết quả không xác định, có thể hỏng ở máy khác hoặc lần chạy khác.
  • Quên hẳn destructor. Chương trình vẫn chạy, chỉ thiếu dòng thông báo, và bộ nhớ của mọi bài hát không được trả lại.

8. Ba lỗi hay gặp với con trỏ ​

Dùng dấu chấm thay cho mũi tên. Viết songs[i].show() thì g++ báo một dòng rất dài, nhưng cuối dòng đã gợi ý cách sửa:

text
main.cpp: In member function 'void Playlist::listAll() const':
main.cpp:54:22: error: request for member 'show' in '*(((Song**)((const Playlist*)this)->Playlist::songs) + ((sizetype)(((long long unsigned int)i) * 8)))', which is of pointer type 'Song*' (maybe you meant to use '->' ?)
   54 |             songs[i].show();
      |                      ^~~~

Dùng kết quả tìm kiếm mà không kiểm tra nullptr. Thay dòng tìm "Khong co" trong main bằng:

cpp
    p.findByTitle("Khong co")->show();  // SAI: khong kiem tra nullptr
    cout << "Dong nay co in ra khong?" << endl;

g++ không báo gì. Chạy thì chương trình dừng im lặng ngay tại dòng đó:

text
Danh sach day, khong them duoc: Bai thu ba
Danh sach Di hoc:
  Hello Viet Nam (4 phut 23 giay)
  Mua he (3 phut 35 giay)
Tim thay: Mua he

Không có thông báo lỗi, không có dòng Dong nay co in ra khong?, destructor cũng không kịp chạy. Trong PowerShell, gõ $LASTEXITCODE ngay sau khi chạy sẽ thấy -1073741819, mã Windows cho "truy cập vùng nhớ không hợp lệ". Gặp chương trình dừng giữa chừng kiểu này, hãy nhìn dòng cuối cùng in ra được, rồi tìm con trỏ được dùng ngay sau đó.

Quên return nullptr; ở cuối hàm trả con trỏ. Lần này g++ có cảnh báo, và đừng bỏ qua nó:

text
main.cpp: In member function 'Song* Playlist::findByTitle(const std::string&) const':
main.cpp:48:5: warning: control reaches end of non-void function [-Wreturn-type]
   48 |     }
      |     ^

Chạy thì chương trình cũng dừng im lặng, đúng lúc tìm một bài không có trong danh sách.

Bài 5.1 — Đóng kín lớp Document (40 phút) ​

Mục tiêu 40 phút40:00Chưa bắt đầu

Nhiệm vụ:

  1. Chuyển cả ba thuộc tính của Document từ public sang private, rồi biên dịch lại. Nếu main.cpp tuần 4 chỉ gọi constructor và display() như đề yêu cầu thì vẫn qua. Thêm tạm vào main một dòng gán thẳng thuộc tính, ví dụ d1.year = 1800;, rồi biên dịch lần nữa: lần này g++ báo lỗi. Đọc kỹ thông báo lỗi đó, nó nói đúng điều tính đóng gói làm được. Đọc xong thì xoá dòng thử.
  2. Thêm thuộc tính int copies — số bản còn trên kệ. Constructor có tham số nhận thêm số bản: Document(id, title, year, copies); constructor mặc định đặt copies = 0.
  3. Thêm các getter (chỉ đọc, phải có const): getId(), getTitle(), getYear(), getCopies().
  4. Thêm các setter có kiểm tra:
    • setTitle(newTitle) — nếu chuỗi rỗng thì in cảnh báo và giữ nguyên giá trị cũ.
    • setYear(newYear) — nếu ngoài khoảng [1900, 2026] thì in cảnh báo và giữ nguyên.
